# 核心技术通俗解释

这份文档的目的，是把项目里出现的重要技术点用尽量通俗的方式解释清楚，方便我自己理解，也方便我以后向老师讲的时候不至于只会背功能名称。

## 1. Go 是什么，为什么适合这个项目

Go 是一种编程语言。它的特点之一是比较适合写网络程序、服务端程序和并发任务。

这个项目里很多功能本质上都和网络请求有关，比如：

- 探测端口
- 访问 URL
- 批量发请求
- 同时扫描多个目标

Go 在这些场景里比较方便，因为：

1. 自带网络库
2. 写 HTTP 服务简单
3. 处理并发任务比较自然
4. 编译后运行方便

所以我这个项目最后用 Go 来写后端是合适的。

## 2. HTTP 服务是什么

HTTP 服务可以理解成一个一直在监听请求的程序。浏览器打开页面、点击按钮、发扫描请求，本质上都是在给后端发送 HTTP 请求。

在这个项目里：

- 浏览器是请求发起方
- Go 程序是接收请求并处理的服务端

例如：

- `/scan/ports` 负责端口扫描
- `/scan/dirs` 负责目录扫描
- `/scan/poc` 负责 POC 扫描
- `/ai/analyze` 负责 AI 分析

所以可以把后端理解成一个“功能接口集合”，前端只是调用这些接口。

## 3. 前后端分离是什么

前后端分离的意思，不一定非要用 Vue、React 才算。只要前端页面和后端逻辑职责分开，其实就是一种前后端分离。

这个项目中：

- 前端负责页面、输入框、按钮、显示结果
- 后端负责真正的扫描和业务逻辑

前端不直接做扫描，前端只是把参数发给后端，再接收后端结果。

这就是这个项目里的前后端分离。

## 4. API 是什么

API 可以理解为后端提供给前端调用的功能入口。

比如老师可以把它理解成“后端开放的一组功能按钮”，只是这些按钮不是直接在页面上，而是以网址接口的形式存在。

例如：

- 调用 `/scan/ports`，就是让后端去执行端口扫描
- 调用 `/scan/webprobe`，就是让后端去执行 Web 探针

所以 API 本质上就是前后端之间沟通的桥梁。

## 5. SSE 是什么，为什么要用它

这是我自己最需要讲清楚的技术点之一。

SSE 的全称是 `Server-Sent Events`，中文可以理解为“服务器向前端持续推送事件”。

### 5.1 为什么不用普通请求就行

普通 HTTP 请求通常是这样：

1. 前端发一个请求
2. 后端处理完以后一次性返回结果
3. 连接结束

这个方式适合很快完成的操作，但不适合扫描任务。

因为扫描类任务往往需要一段时间。如果用户点击“开始扫描”以后必须等几十秒，什么都看不到，体验会很差。

### 5.2 SSE 的作用

SSE 解决的就是这个问题。

它的工作方式可以理解成：

1. 前端先发起一个长连接
2. 后端在任务执行过程中，不断往这条连接里写消息
3. 前端一边接收，一边更新页面

这样用户就能实时看到：

- 扫描进度
- 当前完成多少
- 刚发现了什么结果
- 任务什么时候结束

### 5.3 用生活化的话解释 SSE

如果普通 HTTP 请求像“寄一封信，等对方回一封信”，那么 SSE 更像“打通电话后，对方边做事边向你汇报”。

这非常适合扫描系统。

### 5.4 这个项目里 SSE 用在哪里

这个项目里，很多任务都用了 SSE，比如：

- 端口扫描
- 目录扫描
- POC 扫描
- Web 探针
- WAF 测试
- 批量 EXP 生成
- 自动化扫描工作流

### 5.5 为什么 SSE 对这个系统重要

因为没有 SSE，系统就会变成：

- 用户点击按钮后长时间没反馈
- 不知道扫描进行到哪一步
- 不知道中间发现了什么

用了 SSE 以后，系统就更像一个完整的平台，而不是“点一下等最终结果”的黑盒工具。

## 6. 异步任务是什么

异步任务的核心思想是：

一个操作很耗时，就不要阻塞整个系统，而是把它当作一个单独任务在后台执行。

这个项目中，端口扫描、目录扫描、POC 扫描等都不是瞬间完成的，所以后端会先创建一个任务，再让这个任务慢慢执行。

任务一般会有：

- 任务 ID
- 总进度
- 已完成数量
- 当前状态

这样前端可以通过任务 ID 去跟踪执行过程。

## 7. 并发是什么

并发可以简单理解为“同时处理很多事情”。

比如端口扫描如果一个端口一个端口按顺序扫，会非常慢；如果同时扫很多端口，速度就会快很多。

所以这个项目很多地方都用了并发思想，例如：

- 同时测试多个端口
- 同时请求多个 URL
- 同时验证多个规则

并发并不等于无限开很多任务，因为开太多也会带来压力，所以系统里一般还会设置并发数限制。

## 8. JSON 和 YAML 是什么

JSON 和 YAML 都是用来描述数据的格式。

在这个项目里，它们的重要作用是：

1. 作为前后端接口的数据格式
2. 作为 POC/EXP 规则文件的描述格式

例如：

- 前端给后端发扫描参数时，常常用 JSON
- 漏洞模板文件很多是 YAML

它们的本质作用就是“把规则和参数用结构化方式写出来，让程序能读懂”。

## 9. POC 和 EXP 的区别是什么

这是老师很可能会问到的。

### 9.1 POC

POC 更偏“验证漏洞是否存在”。

它主要回答的是：

**这个目标可能有没有这个漏洞？**

### 9.2 EXP

EXP 更偏“真正利用漏洞”。

它主要回答的是：

**如果这个漏洞存在，我能不能利用它做进一步操作？**

### 9.3 在项目里的关系

在我的系统里：

1. 先用 POC 做检测
2. 再在需要时用 EXP 做利用验证
3. AI 还能帮助生成 EXP

所以二者是层层递进的关系。

## 10. Web 指纹识别是什么

Web 指纹识别可以理解为“根据网页特征猜测目标是什么系统或框架”。

判断依据可能包括：

- 响应头
- 页面标题
- 特殊关键词
- favicon 哈希
- Cookie 特征

这个技术的意义在于：

如果系统提前知道目标可能是 ThinkPHP、WordPress、Spring、PHP 或 Java，就能更有针对性地做后续扫描。

## 11. 字典扫描是什么

字典扫描的意思是：

程序拿着一份预先准备好的路径或关键词列表，逐个去尝试访问目标，看哪些存在。

例如目录扫描里，字典就是一批可能的路径。

字典扫描的优点是简单有效，但缺点是依赖字典质量。因此项目里也支持不同字典文件。

## 12. WAF 是什么

WAF 全称是 Web Application Firewall，也就是 Web 应用防火墙。

它的作用是拦截一些看起来像攻击的请求。

所以项目中的 WAF 绕过测试，本质是在研究：

- 某些攻击 payload 会不会被拦截
- 经过编码或变形后，是否更容易通过

这部分更偏安全研究和实验性质。

## 13. AI Provider 是什么

AI Provider 可以理解为“不同的大模型服务提供方”。

这个项目里支持多种 AI 类型，比如：

- OpenAI
- DeepSeek
- Anthropic
- Ollama

系统把这些统一抽象成一种 AI 接口，这样调用时不用每个地方都重新写一套逻辑。

这样做的好处是：

1. 后续更容易切换模型
2. 同一个功能可以接不同 AI
3. 扩展性更好

## 14. MCP 是什么

MCP 可以理解为一种让 AI 与外部工具连接和交互的协议机制。

在我的项目里，MCP 主要和 JADX 这类逆向分析工具有关。

它的意义在于：

AI 不只是纯聊天，还能通过 MCP 调用外部工具、获取额外上下文、完成更复杂的分析。

从系统定位来说，这部分属于增强能力，不是最基础的扫描主线，但它体现了系统扩展到逆向辅助分析的可能性。

## 15. 为什么这个项目里会调用 Python

后端主体是 Go，但 AI 生成利用脚本时，很多情况下生成的是 Python 代码。

这是因为：

1. Python 写漏洞利用脚本比较常见
2. requests 等库适合快速构造 HTTP 利用逻辑
3. AI 生成 Python 利用代码比较自然

所以项目中出现了一种“Go 调度 + Python 执行”的组合方式。

这不是冲突，而是分工：

- Go 负责平台和流程
- Python 负责具体的利用脚本执行

## 16. 为什么要做自动验证和自动修正

如果 AI 只负责生成代码，实际问题是：代码不一定能直接运行。

因此系统进一步做了：

1. 自动执行 AI 生成的脚本
2. 读取标准输出和错误输出
3. 分析失败原因
4. 把失败信息交给 AI 再修一次

这个流程可以理解成一个闭环。

它体现了系统不是只生成“看起来像代码的文本”，而是尽量去逼近“能实际运行的结果”。

## 17. 报告数据为什么要汇总

一个综合扫描系统如果只有单模块结果，是不够完整的。

例如：

- 端口扫描结果在一页
- POC 结果在一页
- WAF 结果在另一页

这样不方便老师看，也不方便自己总结。

所以项目里有报告模块，目的是把各模块结果整合在一起，变成一份更完整的扫描结果材料。

## 18. 我最需要真正理解的几个技术关键词

如果只抓最关键的，我认为我至少要把下面几个概念讲明白：

1. HTTP 服务：后端如何提供功能接口
2. API：前端如何调用后端功能
3. SSE：为什么能实时显示进度
4. 异步任务：为什么扫描不会卡死页面
5. 并发：为什么扫描速度会更快
6. JSON/YAML：为什么能用规则文件描述漏洞
7. POC/EXP：为什么检测和利用是两层逻辑
8. AI Provider：为什么系统能接不同模型
9. 自动验证：为什么 AI 生成脚本后还要再执行和修正

只要我把这些点讲明白，老师问到系统原理时，我就不会只停留在“这个按钮有什么用”这个层面。
