# 第6章 系统测试

## 6.1 测试目的

系统测试的目标在于验证 NeonScan 2.0 的功能正确性、实时反馈能力、模块联动能力与运行稳定性。与 1.0 版本相比，2.0 的测试重点不再局限于单一扫描模块是否可用，而是扩展到统一任务管理、SSE 事件推送、AI 自动扫描编排、Python EXP 生成与自动验证闭环、JADX MCP 会话管理、上传隔离与报告恢复等完整链路。

对于本系统而言，测试主要包括以下几个方面：验证端口扫描、目录扫描、POC 扫描、EXP 执行、Web 探测、WAF 绕过、资产收集等基础模块能够正常工作；验证任务创建、进度更新、停止与自动清理机制是否稳定；验证前端是否能够通过 SSE 实时接收消息并在页面刷新后恢复任务状态；验证 AI 模块是否能够完成自动扫描、Python EXP 生成、批量生成和自动验证修正；验证 JADX MCP 会话管理与流式对话功能是否可用；验证上传文件目录隔离、7 天清理和报告汇总导出等工程能力是否满足预期。

## 6.2 测试方法

本系统测试综合采用白盒测试与黑盒测试方法。白盒测试主要用于检查后端路由逻辑、任务调度、规则解析、AI 自动验证闭环和会话管理实现是否符合设计预期；黑盒测试则主要从用户视角验证各模块页面、接口输入输出、任务进度显示和结果汇总是否满足使用需求。

### 1. 代码测试

代码测试围绕正常数据、异常数据和错误数据展开。对于端口扫描模块，输入合法主机与端口范围，验证 TCP/UDP 扫描与 Banner 抓取是否正常；输入非法主机或错误端口格式，验证错误处理逻辑。对于目录扫描模块，测试内置字典和自定义字典上传，验证工作池并发、状态码判定和结果记录；对于 POC 扫描模块，分别使用 Legacy、X-Ray、Nuclei 子集规则测试兼容性；对于 EXP 执行模块，测试多步骤执行、变量提取、Cookie 贯穿和步骤验证。

针对 2.0 新增能力，重点测试 AI 生成 Python EXP、批量生成、自动验证重试和失败修正逻辑；测试 POC 结果是否能够成功归一化为 `ExpSpec`；测试 AI 自动扫描是否能够串联多种内置工具；测试 JADX MCP 会话状态、消息记录与流式聊天逻辑；测试上传目录是否按 `uploads/u-*` 进行隔离，以及过期目录清理是否按策略执行。经检查，代码逻辑与模块实现能够满足设计要求。

### 2. 程序功能测试

程序功能测试面向实际使用流程展开，对各个功能页面进行反复操作和组合测试。对于扫描模块，分别测试端口扫描、目录扫描、POC 扫描、EXP 执行、Web 探测和 WAF 绕过是否能够正常发起任务并稳定返回结果；对于资产收集模块，测试 FFUF、URLFinder、Packer-Fuzzer 相关能力及结果回流；对于 AI 模块，测试自动化扫描工作流、单个 Python EXP 生成、批量生成和自动验证闭环；对于 MCP 模块，测试 JADX 连接、会话状态查询、消息历史获取和流式对话；对于报告页面，测试结果汇总、刷新、清空与导出；对于前端持久化，测试页面刷新后的任务恢复和表单恢复能力。

经过多轮测试，系统在测试环境下能够稳定运行，重复点击、重复启动任务和页面切换未导致明显崩溃现象，符合项目的设计目标。

### 3. 分调和总调综合测试

分调阶段对各个模块进行独立测试：任务管理模块测试任务创建、SSE 推送、任务停止和自动清理；端口扫描模块测试 TCP/UDP 探测与 Banner 抓取；目录扫描模块测试字典读取与工作池并发；POC 扫描模块测试三类规则解析与执行；EXP 执行模块测试多步骤利用链；资产收集模块测试 FFUF、URLFinder、Packer-Fuzzer 调用与结果合并；JADX MCP 模块测试连接、消息与状态查询；AI 模块测试自动扫描、EXP 生成、批量生成和自动验证修正；前端模块测试任务恢复、报告汇总和 localStorage 持久化。

总调阶段则把各模块串联为完整流程：先通过资产收集与 Web 探测获得目标信息，再执行目录扫描和 POC 扫描；对命中的漏洞结果生成 `ExpSpec`，随后调用 AI 生成 Python EXP，并进入自动验证与失败修正流程；最终将多模块结果统一汇总到报告页面。综合测试结果表明，系统能够较稳定地支撑 2.0 所定义的闭环工作流。
