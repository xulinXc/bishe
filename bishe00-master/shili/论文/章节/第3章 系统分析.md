# 第3章 系统分析

## 3.1 可行性分析

一体化安全扫描平台是网络安全工程化发展的直接产物。面对 Web 应用、移动应用与前端资源快速增长的现状，单一工具难以覆盖“发现—验证—利用—取证”全过程，构建具备任务编排、实时反馈、数据回流和 AI 辅助能力的轻量平台具有现实意义。NeonScan 2.0 以统一 HTTP 服务为基础，将传统扫描、外部工具、AI 与 MCP 会话分析纳入同一执行框架，具备较强的技术落地价值。

### 3.1.1 技术可行性

本系统采用 B/S 模式，前端使用静态 HTML、JavaScript、CSS 构建多页面界面，后端使用 Go 语言实现单进程 HTTP 服务。该模式部署简单、维护成本低，便于在实验环境和教学环境中快速落地。Go 语言具有跨平台、并发模型轻量、标准库完善等特点，尤其适合端口扫描、目录枚举、POC 验证、Web 探测等高并发 I/O 任务。系统基于 goroutine 和 channel 组织异步任务，配合统一的 Task 与 SSEMessage 数据结构，实现长任务的创建、进度更新、实时推送、停止和回收。

在功能实现上，系统已经形成较完整的 2.0 技术链路：端口扫描、目录扫描、POC 扫描、EXP 执行、Web 指纹探测、WAF 绕过、JS/API 资产收集、上传隔离、报告汇总等基础能力均已实现；AI 层通过统一的 AI Provider 抽象兼容 DeepSeek、OpenAI、Anthropic、Ollama；AI 自动扫描能够调用系统内置扫描工具；POC 扫描结果可进一步归一化为 ExpSpec，再由 AI 生成 Python EXP，并进入自动验证、失败分析、迭代修正和批量生成流程；MCP 集成部分当前已落地 JADX 会话模型，支持 APK 反编译辅助分析。由此可见，本系统在技术上具有可实现性和可扩展性。

### 3.1.2 经济可行性

本系统的开发环境以开源工具为主，后端采用 Go 1.21，前端采用静态页面技术，开发与调试可直接基于 Visual Studio Code 完成，不需要额外采购商业级运行环境。系统采用单体服务架构，可编译为单一可执行文件，部署成本较低；前端静态资源由同一 HTTP 服务直接提供，省去了额外 Web 服务器配置。外部工具如 FFUF、URLFinder、Packer-Fuzzer 等可按需集成，适合毕设与教学环境的资源条件，因此整体经济成本可控。

## 3.2 设计思路与研究方法

NeonScan 2.0 的设计思路不是简单堆叠扫描工具，而是围绕统一任务流和结果闭环来组织功能。用户在前端页面选择目标与扫描模块后，系统创建任务对象，为其分配唯一任务 ID，并通过 SSE 事件流持续推送扫描进度与发现结果。这样既保证了长任务执行时的实时可见性，也便于用户在页面刷新后继续恢复任务状态。

系统采用“资产发现—漏洞验证—利用生成—自动校验—报告汇总”的闭环设计。首先，资产收集模块通过 FFUF、URLFinder 和 Packer-Fuzzer 收集可访问路径、JS 文件与 API 线索；其次，目录扫描、Web 探测与 POC 扫描对目标进行验证；随后，系统根据 POC 扫描结果提取关键信息并归一化为 ExpSpec；在此基础上，AI 模块可生成单个或批量 Python EXP，并通过自动验证模块执行脚本、分析失败原因、请求 AI 修正并重试，直至验证成功或达到最大次数。最终，各模块结果统一汇总到报告页面，并支持导出与后续分析。

在研究方法上，本文主要采用模块化设计、代码实现验证和场景化测试相结合的方法：先从端口扫描、目录扫描、POC 扫描等基础模块出发，构建统一数据结构和任务调度机制；再引入外部工具和 MCP 会话模型扩展分析能力；最后利用 AI 自动扫描与 AI-EXP 自动验证闭环增强系统的智能化与自动化水平。

## 3.3 功能需求分析

本系统围绕安全扫描与漏洞验证任务，形成如下功能需求。

1. 端口扫描功能  
(1) 支持 TCP 和 UDP 两种协议的端口扫描。  
(2) 支持自定义端口范围、并发数和超时时间。  
(3) 支持可选的 Banner 抓取。  
(4) 通过 SSE 实时推送开放端口和扫描进度。  
(5) 支持任务停止与统一进度管理。  

2. 目录扫描功能  
(1) 支持内置字典与自定义字典上传。  
(2) 支持多字典并发扫描与工作池模式。  
(3) 判定有效状态码并记录响应长度与 Location。  
(4) 通过任务模型统一反馈进度与结果。  
(5) 扫描结果可参与后续报告汇总。  

3. POC 扫描功能  
(1) 支持 Legacy、X-Ray、Nuclei 子集三种规则格式。  
(2) 支持状态码、响应体和响应头的组合匹配。  
(3) 支持变量替换与多种规则兼容。  
(4) 输出命中结果与可复现信息。  
(5) 为后续 ExpSpec 归一化和 EXP 生成提供输入。  

4. EXP 执行功能  
(1) 支持多步骤编排。  
(2) 支持变量提取与替换。  
(3) 支持 Cookie 自动贯穿。  
(4) 支持重试与休眠机制。  
(5) 输出步骤命中情况和最终执行状态。  

5. Web 探测功能  
(1) 批量采集标题、协议、状态码等基础信息。  
(2) 识别 Server、X-Powered-By、Cookie、CMS 迹象等指纹。  
(3) 支持 favicon SHA1 和 robots.txt 检测。  
(4) 支持 URL 去重与自动补全协议。  
(5) 为目标画像和后续筛选提供依据。  

6. WAF 绕过功能  
(1) 支持大小写变形、URL 编码/双编码、路径填充等策略。  
(2) 支持多方法组合测试。  
(3) 支持通过状态码或关键字判定有效入口。  
(4) 支持结果筛选与展示。  
(5) 为进一步验证提供可用载荷。  

7. 资产收集功能  
(1) 支持目标可解包性分析。  
(2) 支持调用 Packer-Fuzzer 进行 JS 解包尝试。  
(3) 支持调用 FFUF 进行路径发现。  
(4) 支持调用 URLFinder 提取 URL 与 JS 链接。  
(5) 结果支持按 js、api、other 分类并回流至目录扫描、POC 扫描和 Web 探测模块。  

8. MCP 集成功能  
(1) 支持 JADX MCP 会话连接与状态查询。  
(2) 支持反编译分析过程中的消息历史管理。  
(3) 支持流式对话与工具调用。  
(4) 支持 APK 分析相关结果获取。  
(5) 为移动应用安全分析提供辅助能力。  

9. AI 分析与利用生成功能  
(1) 支持配置 DeepSeek、OpenAI、Anthropic、Ollama 等 AI 提供商。  
(2) 支持 AI 自动扫描工作流。  
(3) 支持基于 ExpSpec 的 Python EXP 生成。  
(4) 支持批量生成 Python EXP。  
(5) 支持自动验证、失败分析与迭代修正闭环。  

10. 文件上传功能  
(1) 支持上传字典、POC、EXP、APK 等资源文件。  
(2) 单文件大小限制不超过 512MB。  
(3) 文件保存到隔离目录 `uploads/u-*`。  
(4) 支持 7 天异步清理机制。  

11. 扫描报告与前端状态管理功能  
(1) 聚合各模块扫描结果形成统一报告。  
(2) 支持页面刷新后的任务恢复。  
(3) 支持前端 localStorage 持久化表单状态与运行任务。  
(4) 支持报告刷新、清空与导出。  
(5) 支持为论文和测试章节提供可复核结果。
