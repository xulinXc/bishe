## 5.1 任务管理模块核心代码

### 核心代码片段
- `newTask` 函数：创建新任务
- `sseHandler` 函数：SSE事件流处理器

### 为什么是核心代码
任务管理模块是整个系统的**基础设施**，所有扫描模块都依赖它来管理任务生命周期和实时通信。没有任务管理，系统无法实现异步扫描和实时进度推送。

### 核心在哪里
1. **`newTask`函数**：
   - **唯一性保证**：使用`time.Now().UnixNano()`生成唯一任务ID，避免任务冲突
   - **并发安全**：使用`mu.Lock()`保护全局任务表，防止并发写入导致的数据竞争
   - **资源初始化**：创建带缓冲区的通道（容量1024），平衡内存占用和性能
   - **停止机制**：初始化`stop`通道，支持优雅停止任务

2. **`sseHandler`函数**：
   - **实时通信**：通过Server-Sent Events实现服务器主动推送，无需前端轮询
   - **连接管理**：监听`r.Context().Done()`检测客户端断开，及时释放资源
   - **任务同步**：监听`t.stop`通道，任务停止时发送结束消息
   - **消息转发**：从任务通道`t.ch`读取消息并转发给前端，实现解耦

### 作用
- **任务生命周期管理**：统一管理所有扫描任务的创建、执行、停止和清理
- **实时进度推送**：通过SSE实现前端实时显示扫描进度和结果
- **资源隔离**：每个任务有独立的通道和停止信号，互不干扰
- **内存管理**：通过任务清理守护进程（Janitor）自动清理过期任务，防止内存泄漏

### 完整代码及逐行说明

#### 1. newTask 函数

```go
func newTask(total int) *Task {
    // 第67行：生成唯一任务ID（基于当前时间戳）
    // time.Now().UnixNano() 获取纳秒级时间戳，确保ID唯一性
    // fmt.Sprintf 格式化为字符串，前缀"t-"便于识别任务ID
    id := fmt.Sprintf("t-%d", time.Now().UnixNano())
    
    // 第69-76行：创建任务结构体并初始化所有字段
    t := &Task{
        ID:      id,                                    // 任务唯一标识符
        Total:   total,                                 // 任务总数（如需要扫描的端口数）
        Done:    0,                                     // 已完成数量，初始为0
        Created: time.Now(),                           // 任务创建时间，用于后续清理判断
        ch:      make(chan SSEMessage, 1024),          // SSE消息通道，容量1024，带缓冲区避免阻塞
        stop:    make(chan struct{}),                  // 停止信号通道，用于优雅停止任务
    }
    
    // 第78-80行：将任务添加到全局任务表（并发安全）
    mu.Lock()        // 获取全局互斥锁，防止并发写入
    tasks[id] = t    // 将任务添加到全局任务映射表
    mu.Unlock()      // 释放锁
    
    return t         // 返回创建的任务对象
}
```

**关键点说明**：
- **第68行**：使用纳秒级时间戳确保ID唯一性，避免任务冲突
- **第74行**：通道容量1024，平衡内存占用和性能，避免消息丢失
- **第75行**：`stop`通道用于发送停止信号，所有goroutine监听此通道
- **第78-80行**：使用互斥锁保护全局任务表，确保并发安全

```go
func sseHandler(w http.ResponseWriter, r *http.Request) {
    // 第234行：从URL查询参数中获取任务ID
    // 前端通过 /events?task=t-xxx 连接SSE流
    id := r.URL.Query().Get("task")
    
    // 第235-238行：验证任务ID是否存在
    if id == "" {
        http.Error(w, "missing task", http.StatusBadRequest)  // 返回400错误
        return
    }

    // 第241-245行：从全局任务表中获取任务对象
    t, ok := getTask(id)  // getTask是线程安全的函数
    if !ok {
        http.Error(w, "task not found", http.StatusNotFound)  // 任务不存在，返回404
        return
    }

    // 第248-250行：设置SSE响应头
    // Content-Type: text/event-stream 是SSE协议要求的响应头
    w.Header().Set("Content-Type", "text/event-stream")  // SSE协议标识
    w.Header().Set("Cache-Control", "no-cache")          // 禁用缓存
    w.Header().Set("Connection", "keep-alive")            // 保持连接

    // 第252行：获取请求上下文，用于检测客户端断开连接
    ctx := r.Context()
    
    // 第253行：创建15秒的心跳定时器，定期发送ping消息保持连接活跃
    ticker := time.NewTicker(15 * time.Second)
    defer ticker.Stop()  // 函数返回时停止定时器，释放资源

    // 第257-259行：发送开始消息，通知前端任务已开始
    if err := writeSSE(w, SSEMessage{
        Type:     "start",                              // 消息类型：开始
        TaskID:   id,                                   // 任务ID
        Progress: fmt.Sprintf("0/%d", t.Total),        // 进度文本：0/总数
        Percent:  0,                                    // 进度百分比：0%
    }); err != nil {
        return  // 发送失败则直接返回
    }

    // 第262-298行：主循环，监听多个通道事件
    for {
        select {
        case <-ctx.Done():
            // 第264-266行：客户端断开连接
            // ctx.Done() 在客户端关闭连接时会被触发
            return  // 直接返回，释放资源

        case <-t.stop:
            // 第267-275行：任务停止信号
            // 当任务被停止时，t.stop通道会被关闭，触发此case
            _ = writeSSE(w, SSEMessage{
                Type:     "end",                        // 消息类型：结束
                TaskID:   id,
                Progress: fmt.Sprintf("%d/%d", func() int { 
                    t.m.Lock()                          // 获取任务锁
                    defer t.m.Unlock()                 // 确保释放锁
                    return t.Done                       // 返回已完成数量
                }(), t.Total),
                Percent:  100,                          // 进度100%
            })
            return  // 发送结束消息后返回

        case <-ticker.C:
            // 第276-280行：心跳消息（每15秒发送一次）
            // 保持连接活跃，防止代理服务器或浏览器超时断开
            if err := writeSSE(w, SSEMessage{
                Type:   "ping",                         // 消息类型：心跳
                TaskID: id,
            }); err != nil {
                return  // 发送失败则返回
            }

        case msg, ok := <-t.ch:
            // 第281-296行：接收任务消息
            // t.ch 是任务的消息通道，扫描过程中会向此通道发送消息
            if !ok {
                // 第283-291行：通道已关闭
                // 通道关闭表示任务已完成，发送结束消息
                _ = writeSSE(w, SSEMessage{
                    Type:     "end",
                    TaskID:   id,
                    Progress: fmt.Sprintf("%d/%d", func() int { 
                        t.m.Lock()
                        defer t.m.Unlock()
                        return t.Done 
                    }(), t.Total),
                    Percent:  100,
                })
                return
            }
            // 第293-296行：转发消息到前端
            // 将任务发送的消息（progress、find等）转发给前端
            if err := writeSSE(w, msg); err != nil {
                return  // 发送失败则返回
            }
        }
    }
}
```

**关键点说明**：
- **第234行**：从URL参数获取任务ID，前端通过此ID连接对应的SSE流
- **第252行**：使用请求上下文检测客户端断开，及时释放资源
- **第253行**：心跳机制防止连接超时，15秒间隔平衡性能和资源
- **第262-298行**：select语句监听多个通道，实现事件驱动的异步处理
- **第281行**：从任务通道读取消息，实现任务和SSE连接的解耦

## 5.2 端口扫描模块核心代码

### 核心代码片段
- TCP/UDP连接建立逻辑
- Banner抓取逻辑
- 并发控制和进度更新

### 为什么是核心代码
端口扫描是**最基础的扫描功能**，其他扫描模块（如Web探测、目录扫描）通常需要先知道开放端口。TCP和UDP两种协议的扫描逻辑完全不同，需要分别处理。

### 核心在哪里
1. **TCP扫描**：
   - **连接探测**：使用`net.DialTimeout`建立TCP连接，通过连接成功与否判断端口开放状态
   - **超时控制**：设置连接超时，避免长时间等待
   - **Banner抓取**：连接成功后立即读取服务欢迎信息，用于服务识别

2. **UDP扫描**：
   - **无连接协议**：UDP是无连接协议，需要先`ResolveUDPAddr`解析地址
   - **数据包发送**：发送空数据包（`\n`）触发服务响应
   - **响应检测**：通过`ReadFrom`读取响应，有响应则端口开放

3. **并发控制**：
   - **信号量模式**：使用`sem`通道限制并发数，防止资源耗尽
   - **WaitGroup同步**：确保所有goroutine完成后再结束任务
   - **进度实时更新**：每次扫描完成后调用`IncDone()`更新进度，通过SSE推送

### 作用
- **端口发现**：快速识别目标主机开放的端口和服务
- **服务识别**：通过Banner信息识别服务类型和版本
- **性能优化**：通过并发控制平衡扫描速度和资源占用
- **实时反馈**：扫描过程中实时推送结果，用户无需等待全部完成

### 完整代码及逐行说明

#### portScanHandler 函数核心部分

```go
func portScanHandler(w http.ResponseWriter, r *http.Request) {
    // 第390-394行：解析HTTP请求体中的JSON数据
    var req PortScanReq
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)  // JSON解析失败，返回400错误
        return
    }
    
    // 第395-399行：解析端口规格字符串（如"1-1024,80,443"）
    ports := parsePorts(req.Ports)  // 解析为端口列表
    if len(ports) == 0 {
        http.Error(w, "no ports", http.StatusBadRequest)  // 没有有效端口，返回400错误
        return
    }
    
    // 第400-409行：设置并发数和超时时间（带默认值）
    cc := req.Concurrency
    if cc <= 0 {
        cc = 500  // 默认并发数500
    }
    timeout := time.Duration(req.TimeoutMs)
    if timeout <= 0 {
        timeout = 300 * time.Millisecond  // 默认超时300毫秒
    } else {
        timeout = time.Duration(req.TimeoutMs) * time.Millisecond  // 转换为time.Duration类型
    }
    
    // 第410行：创建新任务，总数为端口数量
    t := newTask(len(ports))
    
    // 第411行：启动goroutine异步执行扫描（不阻塞HTTP响应）
    go func() {
        // 第412行：创建信号量通道，容量为并发数，用于限制同时扫描的端口数
        sem := make(chan struct{}, cc)
        
        // 第413行：创建WaitGroup，用于等待所有goroutine完成
        var wg sync.WaitGroup
        
        // 第414-417行：确定扫描类型（TCP或UDP），默认TCP
        stype := strings.ToLower(strings.TrimSpace(req.ScanType))
        if stype == "" {
            stype = "tcp"  // 默认TCP扫描
        }
        
        // 第418-483行：遍历所有端口，为每个端口启动一个goroutine
        for _, p := range ports {
            // 第419-423行：检查任务是否已停止（支持中途停止）
            select {
            case <-t.stop:
                break  // 任务已停止，跳出循环
            default:
            }
            
            // 第424行：WaitGroup计数器+1，表示启动了一个goroutine
            wg.Add(1)
            
            // 第425行：获取信号量（如果通道已满则阻塞，限制并发数）
            sem <- struct{}{}
            
            // 第426行：保存端口号到局部变量（避免闭包问题）
            pp := p
            
            // 第427行：启动goroutine扫描单个端口
            go func() {
                defer wg.Done()  // goroutine结束时，WaitGroup计数器-1
                
                // 第429-434行：再次检查任务是否已停止
                select {
                case <-t.stop:
                    <-sem  // 释放信号量
                    return // 直接返回，不执行扫描
                default:
                }
                
                // 第435行：构造目标地址（IP:端口）
                addr := fmt.Sprintf("%s:%d", req.Host, pp)
                
                // 第436-437行：初始化端口状态和Banner变量
                open := false      // 端口是否开放
                var banner string  // Banner信息
                
                // 第438-453行：UDP扫描逻辑
                if stype == "udp" {
                    // 第439行：解析UDP地址
                    udpAddr, err := net.ResolveUDPAddr("udp", addr)
                    if err == nil {
                        // 第441行：创建UDP连接
                        c, err := net.DialUDP("udp", nil, udpAddr)
                        if err == nil {
                            // 第443行：设置读取超时
                            _ = c.SetDeadline(time.Now().Add(timeout))
                            
                            // 第444行：发送空数据包（\n）触发服务响应
                            _, _ = c.Write([]byte("\n"))
                            
                            // 第445-450行：尝试读取响应
                            buf := make([]byte, 256)  // 256字节缓冲区
                            n, _, rerr := c.ReadFrom(buf)  // 读取响应
                            if rerr == nil && n > 0 {
                                open = true                    // 有响应，端口开放
                                banner = string(buf[:n])       // 保存Banner信息
                            }
                            
                            // 第451行：关闭UDP连接
                            _ = c.Close()
                        }
                    }
                } else {
                    // 第454-467行：TCP扫描逻辑
                    // 第455行：建立TCP连接（带超时）
                    conn, err := net.DialTimeout("tcp", addr, timeout)
                    if err == nil {
                        open = true  // 连接成功，端口开放
                        
                        // 第458行：设置读取超时
                        _ = conn.SetDeadline(time.Now().Add(timeout))
                        
                        // 第459-464行：如果启用Banner抓取，尝试读取服务信息
                        if req.GrabBanner {
                            buf := make([]byte, 256)  // 256字节缓冲区
                            n, _ := conn.Read(buf)    // 读取Banner（非阻塞）
                            if n > 0 {
                                banner = string(buf[:n])  // 保存Banner信息
                            }
                        }
                        
                        // 第466行：关闭TCP连接
                        _ = conn.Close()
                    }
                }
                
                // 第469-480行：更新进度并发送结果
                // 第469行：增加已完成计数（线程安全）
                d, tot := t.IncDone()
                
                // 第470行：计算进度百分比
                percent := int(math.Round(float64(d) / float64(tot) * 100))
                
                // 第471行：创建进度消息
                msg := SSEMessage{
                    Type:     "progress",                    // 消息类型：进度
                    TaskID:   t.ID,
                    Progress: fmt.Sprintf("%d/%d", d, tot), // 进度文本：已完成/总数
                    Percent:  percent,                       // 进度百分比
                }
                
                // 第472-479行：如果端口开放，创建find消息
                if open {
                    msg.Type = "find"  // 消息类型：发现
                    data := map[string]interface{}{
                        "port":   pp,        // 端口号
                        "status": "open",    // 状态：开放
                        "proto":  stype,     // 协议：tcp或udp
                    }
                    if banner != "" {
                        data["banner"] = banner  // 如果有Banner，添加到数据中
                    }
                    msg.Data = data
                }
                
                // 第480行：发送消息到SSE通道（线程安全）
                safeSend(t, msg)
                
                // 第481行：释放信号量，允许下一个goroutine执行
                <-sem
            }()
        }
        
        // 第484行：等待所有goroutine完成
        wg.Wait()
        
        // 第485行：标记任务完成
        finishTask(t.ID)
    }()
    
    // 第487-488行：立即返回任务ID给前端（不等待扫描完成）
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(map[string]string{"taskId": t.ID})
}
```

**关键点说明**：
- **第412行**：信号量模式限制并发数，防止创建过多goroutine导致资源耗尽
- **第413行**：WaitGroup确保所有扫描完成后才结束任务
- **第425行**：获取信号量后再启动goroutine，精确控制并发数
- **第426行**：保存端口号到局部变量，避免闭包捕获循环变量的问题
- **第455行**：`DialTimeout`带超时参数，避免长时间等待关闭的端口
- **第469行**：`IncDone()`是线程安全的，多个goroutine并发调用不会出错
- **第480行**：`safeSend`内部处理了并发安全问题，可以安全地从多个goroutine调用

## 5.3 目录扫描模块核心代码

### 核心代码片段
- 字典文件读取和解析
- 工作池模式实现
- 状态码判定逻辑

### 为什么是核心代码
目录扫描是**Web安全测试的基础**，用于发现隐藏的目录和文件。工作池模式是Go语言中处理大量并发任务的经典模式，体现了系统的并发设计能力。

### 核心在哪里
1. **字典解析**：
   - **文件读取**：从文件系统读取字典文件，支持多文件合并
   - **路径规范化**：自动为路径添加`/`前缀，确保URL格式正确
   - **注释过滤**：跳过以`#`开头的注释行，提高可读性

2. **工作池模式**：
   - **任务分发**：通过`jobs`通道分发任务，实现生产者-消费者模式
   - **Worker复用**：固定数量的worker goroutine处理所有任务，避免创建过多goroutine
   - **优雅停止**：监听`t.stop`信号，支持中途停止扫描

3. **状态码判定**：
   - **有效状态码**：200（成功）、301/302（重定向）、403（禁止访问）都视为有效发现
   - **信息记录**：记录响应长度和Location头，用于后续验证和报告
   - **错误处理**：网络错误不终止整个任务，继续扫描其他路径

### 作用
- **资产发现**：发现Web应用的隐藏目录和文件
- **漏洞入口**：找到管理后台、配置文件等敏感路径
- **性能优化**：工作池模式平衡并发数和资源占用，避免系统过载
- **结果记录**：记录详细的响应信息，便于后续分析和验证

func dirScanHandler(w http.ResponseWriter, r *http.Request) {
    // 第506-510行：解析HTTP请求体
    var req DirScanReq
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }
    
    // 第512-521行：验证并规范化基础URL
    u := strings.TrimSpace(req.BaseURL)
    if u == "" {
        http.Error(w, "missing baseUrl", http.StatusBadRequest)
        return
    }
    low := strings.ToLower(u)
    // 如果没有协议前缀，自动添加http://
    if !strings.HasPrefix(low, "http://") && !strings.HasPrefix(low, "https://") {
        u = "http://" + u
    }
    req.BaseURL = u
    
    // 第523-540行：定义字典文件读取函数
    var paths []string
    readOne := func(fp string) error {
        // 第525行：读取字典文件内容
        b, err := os.ReadFile(fp)
        if err != nil {
            return err
        }
        // 第529行：按行分割文件内容
        for _, line := range strings.Split(string(b), "\n") {
            // 第530行：去除首尾空白字符
            p := strings.TrimSpace(line)
            // 第531-533行：跳过空行和注释行（以#开头）
            if p == "" || strings.HasPrefix(p, "#") {
                continue
            }
            // 第534-536行：如果路径不以/开头，自动添加
            if !strings.HasPrefix(p, "/") {
                p = "/" + p
            }
            // 第537行：添加到路径列表
            paths = append(paths, p)
        }
        return nil
    }
    
    // 第542-551行：读取内置字典
    if len(req.BuiltinDicts) > 0 {

                // 第601-609行：创建HTTP请求

                        Type:     "progress",
                        TaskID:   t.ID,
                        Progress: fmt.Sprintf("%d/%d", d, tot),

                    }

                }

                d, tot := t.IncDone()
                percent := int(math.Round(float64(d) / float64(tot) * 100))
                msg := SSEMessage{
                    Type:     "progress",
                    TaskID:   t.ID,
                    Progress: fmt.Sprintf("%d/%d", d, tot),
                    Percent:  percent,
                }
                
                // 第626行：判断是否为有效状态码（200/301/302/403）
                if status == 200 || status == 403 || status == 301 || status == 302 {
                    msg.Type = "find"  // 有效发现
                    msg.Data = map[string]interface{}{
                        "path":     path,     // 路径
                        "url":      url,      // 完整URL
                        "status":   status,   // 状态码
                        "location": loc,      // 重定向地址
                        "length":   bodyLen,  // 响应体长度
                    }
                }
                
                // 第630行：发送消息
                safeSend(t, msg)
            }
        }
        
        // 第634-644行：启动worker goroutine（工作池）
        wN := cc
        if wN < 1 {
            wN = 1  // 至少1个worker
        }
        if wN > 1000 {
            wN = 1000  // 最多1000个worker，防止资源耗尽
        }
        wg.Add(wN)  // WaitGroup计数器设置为worker数量
        for i := 0; i < wN; i++ {
            go worker()  // 启动worker goroutine
        }
        
        // 第646-653行：向jobs通道发送任务（生产者）
        for _, p := range paths {
            select {
            case <-t.stop:
                break  // 任务已停止，停止发送任务
            default:
            }
            jobs <- p  // 发送路径到jobs通道
        }
        close(jobs)  // 关闭通道，通知所有worker任务已发送完毕
        
        // 第654行：等待所有worker完成
        wg.Wait()
        
        // 第655行：标记任务完成
        finishTask(t.ID)
    }()
    
    // 第657-658行：立即返回任务ID
    w.Header().Set("Content-Type", "application/json")
    json.NewEncoder(w).Encode(map[string]string{"taskId": t.ID})
}

func evalRuleExpression(expr string, status int, body []byte, headers http.Header) bool {
    // 第1676-1680行：严格性检查
    // 如果响应体为空且表达式包含bcontains，直接返回false
    if len(body) == 0 && strings.Contains(expr, "bcontains") {
        return false  // 空响应无法进行包含匹配
    }

    ex := expr  // 复制表达式，避免修改原表达式
    
    // 第1684-1694行：替换 response.status == N 格式
    // 正则表达式匹配 response.status == 数字 的模式
    reStatus := regexp.MustCompile(`response\.status\s*==\s*(\d+)`)
    ex = reStatus.ReplaceAllStringFunc(ex, func(s string) string {
        m := reStatus.FindStringSubmatch(s)  // 提取状态码数字
        if len(m) == 2 {
            n, _ := strconv.Atoi(m[1])  // 转换为整数
            if status == n {
                return "true"  // 状态码匹配，替换为true
            }
        }
        return "false"  // 状态码不匹配，替换为false
    })
    
    // 第1696-1710行：替换 response.body.bcontains("...") 格式
    // 支持单引号和双引号，非贪婪匹配
    reContains := regexp.MustCompile(`response\.body\.bcontains\(b?['\"]([\s\S]*?)['\"]\)`)
    ex = reContains.ReplaceAllStringFunc(ex, func(s string) string {
        m := reContains.FindStringSubmatch(s)  // 提取要搜索的字符串
        if len(m) == 2 {
            needle := m[1]  // 要搜索的关键词
            if needle == "" {
                return "false"  // 关键词为空，返回false
            }
            // 检查响应体是否包含关键词
            if len(body) > 0 && strings.Contains(string(body), needle) {
                return "true"
            }
        }
        return "false"
    })
    
    // 第1712-1727行：替换 r'pattern'.bmatches(response.body) 格式（正则匹配）
    reMatchesR := regexp.MustCompile(`r['"]([\s\S]*?)['"]\.bmatches\(response\.body\)`)
    ex = reMatchesR.ReplaceAllStringFunc(ex, func(s string) string {
        m := reMatchesR.FindStringSubmatch(s)
        if len(m) == 2 {
            pat := m[1]  // 正则表达式模式
            if pat == "" || len(body) == 0 {
                return "false"
            }
            re, e := regexp.Compile(pat)  // 编译正则表达式
            if e == nil && re.Match(body) {  // 匹配响应体
                return "true"
            }
        }
        return "false"
    })
    
    // 第1773-1775行：规范化布尔值（True/False -> true/false）
    ex = strings.ReplaceAll(ex, "True", "true")
    ex = strings.ReplaceAll(ex, "False", "false")
    
    // 第1775行：调用布尔表达式求值函数
    return evalBoolExpr(ex)
}

func evalBoolExpr(expr string) bool {
    ex := strings.TrimSpace(expr)
    if ex == "" {
        return false  // 空表达式返回false
    }
    
    // 第1802-1815行：递归处理括号（优先级最高）
    for {
        re := regexp.MustCompile(`\([^()]*\)`)  // 匹配最内层括号
        loc := re.FindStringIndex(ex)
        if loc == nil {
            break  // 没有括号了，退出循环
        }
        inner := ex[loc[0]+1 : loc[1]-1]  // 提取括号内的表达式
        val := evalBoolExpr(inner)         // 递归求值
        replacement := "false"
        if val {
            replacement = "true"
        }
        // 用求值结果替换括号表达式
        ex = ex[:loc[0]] + replacement + ex[loc[1]:]
    }
    
    // 第1817-1842行：处理OR和AND运算符
    orTerms := splitByOperator(ex, "||")  // 按||分割
    result := false
    for _, term := range orTerms {
        andTerms := splitByOperator(term, "&&")  // 按&&分割
        andVal := true
        hasValidTerm := false
        for _, f := range andTerms {
            v := strings.TrimSpace(f)
            if v == "" {
                continue
            }
            hasValidTerm = true
            if v != "true" {
                andVal = false  // AND条件：有一个false就是false
                break
            }
        }
        if hasValidTerm && andVal {
            result = true  // OR条件：有一个true就是true
            break
        }
    }
    return result
}

### 作用

- **自动化测试**：自动化执行复杂的攻击流程，提高测试效率

### 完整代码及逐行说明

func execExp(base string, spec ExpSpec, client *http.Client) (bool, int, int) {
    // 第349-352行：初始化变量
    matchedSteps := 0                    // 匹配的步骤数
    lastStatus := 0                      // 最后一步的HTTP状态码
    vars := make(map[string]string)      // 变量存储（用于步骤间传递数据）
    cookieJar := make(map[string]string) // Cookie存储（自动管理Cookie）

    // 第355行：按顺序执行每个步骤
    for _, st := range spec.Steps {
        // 第357-364行：构建目标URL（支持绝对URL和相对路径）
        rawPath := substVars(st.Path, vars)  // 替换路径中的变量占位符
        low := strings.ToLower(strings.TrimSpace(rawPath))
        url := ""
        // 如果路径是完整的URL（http://或https://开头），直接使用
        if strings.HasPrefix(low, "http://") || strings.HasPrefix(low, "https://") {
            url = rawPath
        } else {
            // 否则拼接基础URL和路径
            url = strings.TrimRight(base, "/") + rawPath
        }
        
        // 第365行：替换请求体中的变量占位符
        body := substVars(st.Body, vars)
        
        // 第366-369行：确定HTTP方法（默认GET）
        m := strings.ToUpper(strings.TrimSpace(st.Method))
        if m == "" {
            m = "GET"
        }
        
        // 第370-373行：计算重试次数（retry+1，至少1次）
        attempts := st.Retry + 1
        if attempts <= 0 {
            attempts = 1
        }
        
        // 第374-376行：初始化响应相关变量
        var resp *http.Response
        var err error
        var b []byte
        
        // 第377-414行：重试循环
        for i := 0; i < attempts; i++ {
            // 第379-382行：构建请求体（每次重试都重新构建，避免body reader被消耗）
            var reqBody io.Reader
            if body != "" {
                reqBody = strings.NewReader(body)  // 创建字符串Reader
            }
            
            // 第383-391行：创建HTTP请求
            req, e := http.NewRequest(m, url, reqBody)
            if e != nil {
                err = e
                // 请求创建失败，如果配置了重试延迟，则休眠后继续下一次尝试
                if st.RetryDelayMs > 0 {
                    time.Sleep(time.Duration(st.RetryDelayMs) * time.Millisecond)
                }
                continue  // 继续下一次重试
            }
            
            // 第393-395行：设置请求头（替换变量占位符）
            for k, v := range st.Headers {
                req.Header.Set(k, substVars(v, vars))  // 替换header值中的变量
            }
            
            // 第397-403行：添加Cookie（从cookieJar中获取之前步骤设置的Cookie）
            if len(cookieJar) > 0 {
                var pairs []string
                for ck, cv := range cookieJar {
                    pairs = append(pairs, fmt.Sprintf("%s=%s", ck, cv))  // 格式：key=value
                }
                req.Header.Set("Cookie", strings.Join(pairs, "; "))  // 多个Cookie用;分隔
            }
            
            // 第404行：发送HTTP请求
            resp, err = client.Do(req)
            
            // 第405-410行：如果请求成功，读取响应体并跳出重试循环
            if err == nil {
                b, _ = io.ReadAll(resp.Body)  // 读取响应体
                resp.Body.Close()              // 关闭响应体
                lastStatus = resp.StatusCode   // 保存状态码
                break  // 请求成功，跳出重试循环
            }
            
            // 第411-413行：如果请求失败且配置了重试延迟，休眠后继续重试
            if st.RetryDelayMs > 0 {
                time.Sleep(time.Duration(st.RetryDelayMs) * time.Millisecond)
            }
        }
        
        // 第415-417行：如果所有重试都失败，跳过此步骤
        if err != nil {
            continue  // 继续下一个步骤
        }
        
        // 第418-420行：如果配置了步骤间休眠，执行休眠
        if st.SleepMs > 0 {
            time.Sleep(time.Duration(st.SleepMs) * time.Millisecond)
        }
        
        // 第422-428行：捕获Set-Cookie头，更新cookieJar
        for _, sc := range resp.Header.Values("Set-Cookie") {
            parts := strings.Split(sc, ";")  // Cookie值可能包含;分隔的属性（如expires、path等）
            kv := strings.SplitN(parts[0], "=", 2)  // 只取第一个=之前的部分（key=value）
            if len(kv) == 2 {
                cookieJar[strings.TrimSpace(kv[0])] = strings.TrimSpace(kv[1])  // 保存到cookieJar
            }
        }
        
        // 第430行：从响应中提取变量（BodyRegex、HeaderRegex）
        extractVars(resp, b, st.Extract, vars)
        
        // 第431-433行：验证步骤是否成功
        if validate(resp, b, st.Validate) {
            matchedSteps++  // 验证通过，匹配步骤数+1
        }
    }
    
    // 第436行：成功判定：所有步骤都匹配且至少有一个步骤
    return matchedSteps == len(spec.Steps) && len(spec.Steps) > 0, matchedSteps, lastStatus
}
```

**关键点说明**：
- **第351行**：`vars` map用于在步骤间传递变量，支持复杂的多步骤利用链
- **第352行**：`cookieJar`自动管理Cookie，实现会话保持，支持需要登录的漏洞利用
- **第357行**：`substVars`函数替换变量占位符（如`{{var}}`），实现动态请求构建
- **第377-414行**：重试机制提高成功率，每次重试都重新构建请求，避免body reader被消耗
- **第397-403行**：自动管理Cookie，将之前步骤设置的Cookie自动添加到后续请求中
- **第422-428行**：从Set-Cookie头提取Cookie，更新cookieJar，实现会话保持
- **第430行**：`extractVars`函数通过正则表达式从响应中提取变量，用于后续步骤
- **第431-433行**：`validate`函数验证响应是否符合预期，只有验证通过才计入匹配步骤
- **第436行**：所有步骤都匹配才判定为成功，确保完整的利用链执行成功

    b := strings.ToLower(string(body))

    if strings.Contains(b, "drupal.settings") {
        tech = append(tech, "Drupal")
    }
    
    // 第2644-2646行：检测Generator Meta标签
    if strings.Contains(b, "<meta name=\"generator\"") {
        tech = append(tech, "GeneratorMeta")  // 很多CMS会在meta标签中声明generator

func mutatePayload(p string, strategies []string) []string {
    // 第101行：使用map实现去重（struct{}不占用内存）
    set := map[string]struct{}{p: {}}  // 初始包含原始Payload
    
    // 第102-106行：定义添加函数，将变体添加到set中
    add := func(xs []string) {
        for _, x := range xs {
            set[x] = struct{}{}  // 添加到set（自动去重）
        }
    }
    
    // 第107-121行：遍历策略列表，应用各种变形策略
    for _, s := range strategies {
        s = strings.ToLower(strings.TrimSpace(s))  // 规范化策略名称

        case "doubleencode":
            // 第115行：双重URL编码（调用sDoubleEncode函数）
            add(sDoubleEncode(p))  // 两次URL编码
        case "pathpad":
            // 第117行：路径填充（调用sPathPad函数）

        case "paramsplit":
            // 第119行：参数分割（调用sParamSplit函数）
            add(sParamSplit(p))  // 分割参数

    out := make([]string, 0, len(set))  // 预分配容量

### 5.9.2 JADX MCP 状态查询与流式对话实现

#### 核心代码片段

- `JADXChatStreamHandler`：以 SSE 方式持续推送 AI 对话内容
- `processChatStream`：在流式对话中执行 MCP 工具调用并维护上下文

#### 为什么是核心代码
本系统中的 JADX 集成并不是“单次调用外部命令”这么简单，而是把 APK 反编译工具、AI 对话、MCP 工具调用、前端实时显示四部分连成了一个完整闭环。真正支撑这一闭环的，就是“状态查询”和“流式对话”两类核心代码：前者负责告诉前端当前会话能不能用，后者负责把 AI 生成的内容和 JADX 工具返回结果持续推送给页面。

#### 核心在哪里
1. **服务自启动与连接复用**：
   - `ConnectJADXMCP` 会先检测服务器是否可用，不可用时调用 `startJADXServer`
   - 连接成功后复用 `JADXMCPConnection`，避免每次提问都重新初始化

2. **FastMCP 会话管理**：
   - 使用 `cookiejar` 保存服务端下发的 Cookie
   - `initialize` 请求后由服务端生成 `sessionID`
   - 工具列表通过 `tools/list` 动态获取，而不是在本地写死

3. **状态查询接口**：
   - `GetJADXSessionStatusHandler` 会统一返回 `sessionId`、`apiType`、`hasApiKey`、`mcpConnected`、`messageCount`
   - 前端可以据此判断“是否已配置 AI”、“是否已连接 MCP”、“是否已有历史消息”

4. **SSE 流式对话机制**：
   - `JADXChatStreamHandler` 将响应头设置为 `text/event-stream`
   - `StreamController` 负责缓存消息、管理中止状态、避免浏览器断开后继续写入
   - 后端收到 AI 增量输出后立即 `Flush`，页面可以逐字显示分析结果

5. **工具调用闭环**：
   - `processChatStream` 会保留带 `tool_calls` 的 assistant 消息及其对应的 tool 消息
   - 当 AI 决定调用 MCP 工具时，后端执行 `mcpConn.CallTool`
   - 工具结果会再次写回消息历史，供下一轮 AI 推理继续使用

#### 作用
- **状态可观测**：前端可实时判断 JADX 会话是否可用

        return
    }

    controller := NewStreamController()
    defer controller.Abort()

    session.AddMessage(ChatMessage{
        Role:    "user",
        Content: req.Message,
        Time:    time.Now().Format(time.RFC3339),
    })

    go func() {
        _ = processChatStream(session, req.Message, controller)
    }()

    for {
        select {
        case msg := <-controller.messageChan:
            fmt.Fprintf(w, "data: %s\n\n", msg)
            flusher.Flush()
        case <-controller.abortChan:
            return
        case <-r.Context().Done():
            controller.Abort()
            return
        }
    }
}

- `StreamController` 统一管理“消息发送”和“连接中止”两个动作
- 写入 `data: ...\n\n` 后立刻 `Flush`，浏览器才能实时呈现内容

```go
func processChatStream(session ChatSession, userMessage string, controller *StreamController) error {
    messages := session.GetMessages()
    mcpConn := session.GetMCPConnection()
    apiKey := session.GetAPIKey()
    apiType := session.GetAPIType()
    tools := []AITool{}
    if mcpConn != nil && mcpConn.IsConnected() {
        tools = mcpConn.GetTools()
    }

    var aiProvider interface {
        ChatStream(messages []ChatMessage, tools []AITool, controller *StreamController) (string, []AIToolCall, error)
    }
    switch apiType {
    case "ollama":
        aiProvider = NewOllamaProvider("http://localhost:11434", "gpt-oss:20b")
    case "deepseek":
        provider := NewDeepSeekProvider(apiKey)
        provider.Model = "deepseek-chat"
        aiProvider = provider
    case "openai":
        aiProvider = NewOpenAIProvider(apiKey)
    default:
        return fmt.Errorf("不支持的 API 类型: %s", apiType)
    }

    maxIterations := 10
    iteration := 0
    for iteration < maxIterations {
        iteration++

        fullResponse, toolCalls, err := aiProvider.ChatStream(messages, tools, controller)
        if err != nil {
            return err
        }

        session.AddMessage(ChatMessage{
            Role:      "assistant",
            Content:   fullResponse,
            Time:      time.Now().Format(time.RFC3339),
            ToolCalls: toolCalls,
        })

        if len(toolCalls) == 0 {
            return nil
        }

        for _, toolCall := range toolCalls {
            result, err := mcpConn.CallTool(toolCall.Name, toolCall.Arguments)
            toolMessage := fmt.Sprintf("工具 %s 返回: %v", toolCall.Name, result)
            if err != nil {
                toolMessage = fmt.Sprintf("工具 %s 执行失败: %v", toolCall.Name, err)
            }

            controller.Send(jsonEscape(fmt.Sprintf("\n\n[工具调用结果]\n%s", toolMessage)))
            session.AddMessage(ChatMessage{
                Role:       "tool",
                Content:    toolMessage,
                Time:       time.Now().Format(time.RFC3339),
                ToolCallID: toolCall.ID,
            })
        }

        messages = session.GetMessages()
    }
    return nil
}
```

**关键点说明**：
- 每轮先让 AI 基于历史消息和 MCP 工具描述进行一次推理
- 如果 AI 不再请求工具，则本轮对话结束
- 如果 AI 请求工具，后端执行真实的 MCP 调用，并把结果写入消息历史
- `messages = session.GetMessages()` 使下一轮 AI 能感知刚刚的工具执行结果
- `maxIterations` 是安全阈值，防止模型陷入无限工具调用

## 5.10 AI分析模块核心代码

### 核心代码片段
- `aiAutoScanHandler`：AI 自动扫描编排入口
- `generateEXPForVulnerabilities`：基于漏洞结果生成 EXP 文本说明
- `aiGenPythonFromExpHandler`：生成单个 Python EXP
- `aiGenPythonFromExpBatchHandler`：并发批量生成 Python EXP

- `generateAndVerifyExpScripts`：自动扫描完成后的联动生成与验证

### 为什么是核心代码
AI 模块并不是单一的“调用大模型接口”，而是把“扫描工具编排、漏洞结果理解、EXP 生成、脚本验证、失败修正、结果回传”整合成了完整自动化闭环。该模块直接体现了 NeonScan 与传统扫描器的差异化能力，因此属于论文中最需要展开说明的核心实现。

### 核心在哪里
1. **统一 Provider 抽象**：
   - 同时支持 DeepSeek、OpenAI、Anthropic、Ollama
   - 通过统一接口 `AIProvider` 调用，不把业务逻辑绑死在某一家模型厂商上

2. **AI 驱动的工具编排**：
   - 模型不直接“猜结论”，而是先决定调用哪个工具
   - 工具结果回流到消息历史，再由模型继续做下一步决策

3. **漏洞到利用脚本的转换**：
   - 先把 POC 结果转换成统一 `ExpSpec`
   - 再按漏洞类型生成针对性的 Python 利用脚本

4. **验证与修正闭环**：
   - 生成脚本后不是直接交付，而是先运行验证
   - 如果失败，系统会分析失败原因、构造修正提示词，再次请求 AI 修复

### 作用
- **自动决策**：自动选择扫描顺序和扫描工具
- **自动生成**：自动输出漏洞利用说明和 Python 利用脚本
- **自动验证**：自动执行脚本并校验输出是否符合预期
- **自动修正**：验证失败时自动迭代修改代码

### 5.10.1 AI 自动扫描编排实现

#### 核心代码片段
- `aiAutoScanHandler`
- `executeAITool`
- `getAIScanTools`

#### 为什么是核心代码
自动扫描编排是 AI 模块的总控逻辑。它决定扫描从哪里开始、何时转入 Web 探测、何时触发 POC 扫描，以及在发现漏洞后何时生成 EXP。没有这一层编排，AI 只能做离线报告，无法驱动真实扫描过程。

#### 核心在哪里
1. **请求标准化**：
   - 对目标地址、端口范围、并发数、超时时间进行统一校验和补默认值

2. **系统提示词约束**：
   - 强制 AI 按“端口扫描 → Web 探测 → POC 扫描 → 目录扫描 → EXP 生成”的顺序思考
   - 明确规定 POC 扫描必须使用 `keywords` 参数，避免无差别全量扫描

3. **工具调用循环**：
   - 每一轮先调用 `aiProvider.Chat`
   - 如果返回 `toolCalls`，则执行工具并把结果回写到消息历史
   - 如果返回的是纯文本分析，则判断是否已达到结束条件

4. **结果收束与后处理**：
   - 最后提取最终总结
   - 检查是否存在漏洞结果
   - 如有漏洞则继续触发 EXP 说明生成与 Python 脚本生成验证

#### 完整代码及逐行说明

```go
func aiAutoScanHandler(w http.ResponseWriter, r *http.Request) {
    var req AIAutoScanReq
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, fmt.Sprintf("解析请求失败: %v", err), http.StatusBadRequest)
        return
    }
    if req.Target == "" || req.APIKey == "" {
        http.Error(w, "目标地址和 API Key 不能为空", http.StatusBadRequest)
        return
    }

    if req.Ports == "" {
        req.Ports = "1-1000,3000-4000,8000-9000"
    }

    concurrency := 50
    timeoutMs := 3000
    t := newTask(100)

    go func() {
        allResults := make(map[string]interface{})
        allResults["target"] = req.Target
        allResults["scanTime"] = time.Now().Format("2006-01-02 15:04:05")

        var aiProvider mcp.AIProvider
        switch req.Provider {
        case "deepseek":
            p := mcp.NewDeepSeekProvider(req.APIKey)
            if req.BaseURL != "" {
                p.BaseURL = req.BaseURL
            }
            if req.Model != "" {
                p.Model = req.Model
            }
            aiProvider = p
        case "openai":
            p := mcp.NewOpenAIProvider(req.APIKey)
            if req.BaseURL != "" {
                p.BaseURL = req.BaseURL
            }
            if req.Model != "" {
                p.Model = req.Model
            }
            aiProvider = p
        case "anthropic":
            p := mcp.NewAnthropicProvider(req.APIKey)
            if req.Model != "" {
                p.Model = req.Model
            }
            aiProvider = p
        case "ollama":
            baseURL := "http://localhost:11434"
            if req.BaseURL != "" {
                baseURL = req.BaseURL
            }
            model := "llama2"
            if req.Model != "" {
                model = req.Model
            }
            aiProvider = mcp.NewOllamaProvider(baseURL, model)
        default:
            sendProgress(t, 0, "不支持的AI提供商")
            return
        }
        scanTools := getAIScanTools()

        messages := []mcp.ChatMessage{
            {Role: "system", Content: "你是一位专业的安全扫描专家，负责对目标进行全面的安全扫描。"},
            {Role: "user", Content: fmt.Sprintf("请对目标 %s 进行安全扫描。端口范围：%s", req.Target, req.Ports)},
        }

        maxIterations := 20
        for iteration := 0; iteration < maxIterations; iteration++ {
            response, toolCalls, err := aiProvider.Chat(messages, scanTools)
            if err != nil {
                break
            }

            if response != "" && len(toolCalls) == 0 {
                messages = append(messages, mcp.ChatMessage{Role: "assistant", Content: response})

                responseLower := strings.ToLower(response)
                hasEndPhrase := strings.Contains(responseLower, "扫描完成") ||
                    strings.Contains(responseLower, "分析完成") ||
                    strings.Contains(responseLower, "检测完成") ||
                    strings.Contains(responseLower, "总结") ||
                    strings.Contains(responseLower, "报告已生成")
                isProvidingDetails := strings.Contains(responseLower, "漏洞描述") ||
                    strings.Contains(responseLower, "exp代码") ||
                    strings.Contains(responseLower, "exploit") ||
                    strings.Contains(responseLower, "```python") ||
                    strings.Contains(responseLower, "风险等级") ||
                    strings.Contains(responseLower, "修复建议") ||
                    strings.Contains(responseLower, "利用方法")
                newlineCount := strings.Count(response, "\n")
                isLongSummary := len(response) > 500 && newlineCount > 10

                if hasEndPhrase && !isProvidingDetails && isLongSummary {
                    break
                }
                continue
            }

            if len(toolCalls) > 0 {
                messages = append(messages, mcp.ChatMessage{
                    Role:      "assistant",
                    Content:   response,
                    ToolCalls: toolCalls,
                })

                for _, toolCall := range toolCalls {
                    toolResult := executeAITool(toolCall, req.Target, req.Ports, concurrency, timeoutMs, t, allResults)
                    messages = append(messages, mcp.ChatMessage{
                        Role:       "tool",
                        ToolCallID: toolCall.ID,
                        Content:    toolResult,
                    })
                }
            }
        }

        if pocScan, ok := allResults["pocScan"].(map[string]interface{}); ok {
            if results, ok := pocScan["results"].([]map[string]interface{}); ok && len(results) > 0 {
                expContent := generateEXPForVulnerabilities(allResults, req.Provider, req.APIKey, req.BaseURL, req.Model)
                pyScripts := generateAndVerifyExpScripts(allResults, req.Provider, req.APIKey, req.BaseURL, req.Model, func(msg string) {
                    sendProgress(t, 97, msg)
                })
                allResults["expGenerated"] = expContent
                allResults["expPythonGenerated"] = pyScripts
            }
        }
    }()
}
```

**关键点说明**：
- `newTask(100)` 把整个自动扫描抽象成 0 到 100 的统一进度条
- `messages` 同时保存系统提示词、用户输入、AI回复、工具返回结果
- `toolCalls` 不为空时说明 AI 决定调用真实扫描工具，而不是直接输出结论

- 发现漏洞后不会立刻结束，而是继续执行 EXP 与 Python 利用脚本联动流程

- **让 AI 真正参与扫描调度**
- **把多种扫描工具串成统一工作流**

### 5.10.2 Python EXP 生成与批量生成实现

#### 核心代码片段

func aiGenPythonFromExpBatchHandler(w http.ResponseWriter, r *http.Request) {
    var req AIGenPythonFromExpBatchReq
    if err := json.NewDecoder(r.Body).Decode(&req); err != nil {
        http.Error(w, err.Error(), http.StatusBadRequest)
        return
    }

    exps, err := loadRequestedExps(req.InlineExps, req.ExpPaths, req.ExpDir)
    if err != nil || len(exps) == 0 {
        http.Error(w, "load exps error or empty", http.StatusBadRequest)
        return
    }

    cc := req.Concurrency
    if cc <= 0 {
        cc = 20
    }

    var provider mcp.AIProvider
    if strings.TrimSpace(req.Provider) != "" {
        if p, err := newAIProvider(req.Provider, req.APIKey, req.BaseURL, req.Model); err == nil {
            provider = p
        }
    }

    t := newTask(len(exps))
    go func() {
        sem := make(chan struct{}, cc)
        var wg sync.WaitGroup
        for _, e := range exps {
            wg.Add(1)
            sem <- struct{}{}
            es := e
            go func() {
                defer wg.Done()
                py, keyInfo, _ := generatePythonForSpec(req.TargetBaseURL, es, provider, nil)
                d, tot := t.IncDone()
                safeSend(t, SSEMessage{
                    Type:   "find",
                    TaskID: t.ID,
                    Data: map[string]interface{}{
                        "name": es.Name, "keyInfo": keyInfo, "python": py,
                    },
                })
                <-sem
            }()
        }
        wg.Wait()
        finishTask(t.ID)
    }()

    json.NewEncoder(w).Encode(map[string]string{"taskId": t.ID})
}
```

**关键点说明**：
- `loadRequestedExps` 兼容三种输入方式：内联 EXP、显式路径列表、目录批量加载
- `sem` 控制最大并发数，防止批量调用模型导致资源耗尽
- 每个脚本生成后立刻推送，而不是等全部完成后一次性返回

#### 作用
- **把结构化漏洞信息转成可执行 Python 利用脚本**
- **支持单漏洞快速生成和多漏洞批量生成两种模式**
- **在 AI 失败时提供模板级回退能力**

### 5.10.3 自动验证与迭代修正实现

#### 核心代码片段
- `GenerateAndVerifyExp`
- `verifyExp`
- `analyzeFailure`
- `buildCorrectionPrompt`

#### 为什么是核心代码
传统“AI 生成代码”最大的缺点是结果不稳定。系统为了解决这一问题，引入了“生成后立即运行、失败后自动修正、修正后再次验证”的闭环机制。这部分代码决定了 AI 生成的 EXP 是否真正可用，因此属于 AI 模块中最关键的可靠性保障。

#### 核心在哪里
1. **多轮验证机制**：
   - 默认至少重试 3 次，实际下限提升到 5 次
   - 每次都把当前代码写入临时文件，再真实执行

2. **跨平台 Python 启动策略**：
   - 优先尝试 `python`
   - 失败后尝试 `python3`
   - Windows 下再回退到 `py`

3. **结果判定机制**：
   - 必须检测到 `VULNERABLE` 或 POC 中抽取的标记
   - 对命令执行类还必须能提取有效回显，而不是只输出成功标志

4. **自动修正机制**：
   - 先分析失败原因
   - 再构造针对性的修正提示词
   - 若 AI 修正失败，再走本地备用修复逻辑

#### 完整代码及逐行说明

##### 1. 自动验证主循环 `GenerateAndVerifyExp`

```go
func GenerateAndVerifyExp(config ExpVerifyConfig, provider mcp.AIProvider, logChan chan<- string) (string, error) {
    category := DetectVulnCategory(config.ExpSpec)
    vulnMarker := extractVulnMarker(config.ExpSpec)
    testCmd := getTestCommand(category)

    expDir := filepath.Join(os.TempDir(), "neonscan_exp")
    os.MkdirAll(expDir, 0755)

    maxRetries := config.MaxRetries
    if maxRetries < 3 {
        maxRetries = 5
    }

    currentCode := config.PythonCode
    for attempt := 1; attempt <= maxRetries; attempt++ {
        expFile := filepath.Join(expDir, fmt.Sprintf("exp_attempt_%d.py", attempt))
        os.WriteFile(expFile, []byte(currentCode), 0644)

        result := verifyExp(expFile, config.TargetURL, testCmd, config.TimeoutSec, category, vulnMarker, log)
        if result.Success && result.Matched && result.CanExtract {
            return currentCode, nil
        }

        failureReason := analyzeFailure(result, category, log)
        correctionPrompt := buildCorrectionPrompt(config.ExpSpec, currentCode, failureReason, category, testCmd, result, log)
        correctedCode := requestExpCorrection(provider, correctionPrompt, log)
        if correctedCode != "" {
            currentCode = correctedCode
        } else {
            currentCode = tryAlternativeFix(currentCode, result, category, testCmd, log)
        }
    }

    return "", fmt.Errorf("EXP验证失败，已达到最大重试次数")
}
```

**关键点说明**：
- `extractVulnMarker` 会从原始 POC 中提取验证特征，避免只依赖单一固定标志
- `currentCode` 会在每轮修正后被覆盖，实现“边运行边进化”
- 成功标准不是“脚本能跑起来”，而是 `Success && Matched && CanExtract`

##### 2. 真实执行与结果判定 `verifyExp`

```go
func verifyExp(expFile, targetURL, testCmd string, timeoutSec int, category VulnCategory, vulnMarker string, log func(string, ...interface{})) ExpVerifyResult {
    ctx, cancel := context.WithTimeout(context.Background(), time.Duration(timeoutSec)*time.Second)
    defer cancel()

    pythonCmd := "python"
    if err := exec.Command("python", "--version").Run(); err != nil {
        if err := exec.Command("python3", "--version").Run(); err == nil {
            pythonCmd = "python3"
        } else {
            pythonCmd = "py"
        }
    }

    if !strings.HasPrefix(targetURL, "http://") && !strings.HasPrefix(targetURL, "https://") {
        targetURL = "http://" + targetURL
    }

    cmd := exec.CommandContext(ctx, pythonCmd, expFile, "--target", targetURL, "--cmd", testCmd)
    var stdout, stderr bytes.Buffer
    cmd.Stdout = &stdout
    cmd.Stderr = &stderr
    err := cmd.Run()

    result := ExpVerifyResult{
        Success: err == nil || stderr.Len() > 0 || stdout.Len() > 0,
        Output:  stdout.String(),
        Error:   stderr.String(),
    }

    outputLower := strings.ToLower(result.Output)
    if strings.Contains(outputLower, "vulnerable") || strings.Contains(result.Output, vulnMarker) {
        result.Matched = true
    }

    extractDemo := extractOutput(result.Output, log)
    if extractDemo != "" {
        result.CanExtract = true
        result.ExtractDemo = extractDemo
    }
    return result
}
```

**关键点说明**：
- 通过 `context.WithTimeout` 防止脚本卡死
- 自动补齐 `http://`，解决很多脚本因 URL scheme 缺失而失败的问题
- 对命令执行类漏洞，仅仅输出 `VULNERABLE` 不够，还必须提取到实际回显

##### 3. 失败原因分析与修正提示词构造

```go
func buildCorrectionPrompt(expSpec ExpSpec, currentCode, failureReason string, category VulnCategory, testCmd string, result ExpVerifyResult, log func(string, ...interface{})) string {
    var prompt strings.Builder
    prompt.WriteString("请修正以下Python EXP代码中的问题。\n\n")
    prompt.WriteString(fmt.Sprintf("漏洞类型: %s\n", category))
    prompt.WriteString(fmt.Sprintf("测试命令: %s\n\n", testCmd))
    prompt.WriteString("=== 失败原因分析 ===\n")
    prompt.WriteString(failureReason)
    prompt.WriteString("\n\n")

    if result.Output != "" {
        prompt.WriteString("=== 脚本标准输出 ===\n")
        prompt.WriteString(result.Output)
        prompt.WriteString("\n\n")
    }
    if result.Error != "" {
        prompt.WriteString("=== 脚本错误输出 ===\n")
        prompt.WriteString(result.Error)
        prompt.WriteString("\n\n")
    }

    prompt.WriteString("=== 修正要求 ===\n")
    prompt.WriteString("1. 只输出修正后的完整Python代码\n")
    prompt.WriteString("2. 必须输出 VULNERABLE 或 NOT VULNERABLE\n")
    prompt.WriteString("3. 必须正确处理 URL、参数、输出提取、Windows 兼容问题\n")
    return prompt.String()
}
```

**关键点说明**：
- 提示词不是泛泛而谈，而是把“漏洞类型、测试命令、标准输出、错误输出、修复要求”全部交给 AI
- 这样 AI 修正不是重新瞎写，而是基于真实失败现场进行定向补丁式修复

#### 作用
- **提升 AI 生成脚本的可用率**
- **将“脚本生成”升级为“脚本交付”**
- **降低人工手动调试成本**

### 5.10.4 自动扫描后的联动生成与验证实现

#### 核心代码片段
- `generateAndVerifyExpScripts`
- `normalizeTargetBaseURL`
- `buildExpSpecFromPOCResult`
- `generateEXPForVulnerabilities`

#### 为什么是核心代码
这一部分实现了自动扫描后的“最后一公里”闭环：先由扫描阶段发现漏洞，再自动生成漏洞利用说明，之后把 POC 结果转换为 `ExpSpec`，继续生成 Python 脚本并进入验证修正流程。它把扫描模块和利用模块真正联动起来，是系统智能化程度最高的一段实现。

#### 核心在哪里
1. **POC 结果去重**：
   - 按 `(pocName, url, path)` 组合键去重
   - 防止同一漏洞被重复生成多个脚本

2. **扫描结果转 `ExpSpec`**：
   - `buildExpSpecFromPOCResult` 从扫描结果中抽取 method、path、body、headers、status
   - 统一转换为后续生成器可消费的结构化格式

3. **生成与验证联动**：
   - 先调用 `generatePythonFromExpSpec`
   - 再调用 `GenerateAndVerifyExp`
   - 成功后保存到临时目录，作为已验证脚本输出

4. **自动扫描主流程挂接**：
   - `aiAutoScanHandler` 在确认 `pocScan.results` 非空后，先生成 EXP 说明
   - 再调用 `generateAndVerifyExpScripts` 生成并验证 Python 利用脚本

#### 完整代码及逐行说明

```go
func generateAndVerifyExpScripts(allResults map[string]interface{}, provider, apiKey, baseURL, model string, sendProgress func(string)) []map[string]interface{} {
    pocScan, ok := allResults["pocScan"].(map[string]interface{})
    if !ok {
        return nil
    }
    results, ok := pocScan["results"].([]map[string]interface{})
    if !ok || len(results) == 0 {
        return nil
    }

    seen := make(map[string]bool)
    uniqueResults := make([]map[string]interface{}, 0, len(results))
    for _, r := range results {
        pocName := strings.TrimSpace(toStringValue(r["poc"]))
        url := strings.TrimSpace(toStringValue(r["url"]))
        reqMap, _ := r["req"].(map[string]interface{})
        path := ""
        if reqMap != nil {
            path = strings.TrimSpace(toStringValue(reqMap["path"]))
        }
        dedupKey := pocName + "|" + url + "|" + path
        if seen[dedupKey] {
            continue
        }
        seen[dedupKey] = true
        uniqueResults = append(uniqueResults, r)
    }

    targetBaseURL := normalizeTargetBaseURL(allResults, pocScan)
    aiProvider := createAIProvider(provider, apiKey, baseURL, model, 300)
    scripts := make([]map[string]interface{}, 0, len(uniqueResults))
    logChan := make(chan string, 100)

    for _, r := range uniqueResults {
        specBase, spec, ok := buildExpSpecFromPOCResult(r, targetBaseURL)
        if !ok {
            continue
        }

        py := generatePythonFromExpSpec(specBase, spec)
        config := ExpVerifyConfig{
            TargetURL:  specBase,
            ExpSpec:    spec,
            PythonCode: py,
            Category:   DetectVulnCategory(spec),
            MaxRetries: 3,
            TimeoutSec: 30,
        }

        verifiedCode, err := GenerateAndVerifyExp(config, aiProvider, logChan)
        if err != nil {
            verifiedCode = py
        }

        scripts = append(scripts, map[string]interface{}{
            "name":    spec.Name,
            "keyInfo": buildExpKeyInfo(specBase, spec),
            "python":  strings.TrimSpace(verifiedCode),
        })
        saveExpToFile(spec.Name, verifiedCode)
    }
    return scripts
}
```

**关键点说明**：
- `normalizeTargetBaseURL` 会优先从扫描结果恢复目标基址，避免脚本丢失上下文
- `buildExpSpecFromPOCResult` 是“扫描结果格式”和“脚本生成格式”之间的桥梁
- 生成失败时允许回退到未验证版本，但优先交付验证后的脚本
- `saveExpToFile` 会把最终脚本持久化到临时目录，便于后续下载与复测

#### 与自动扫描主流程的挂接方式

```go

## 5.11 前端界面模块核心代码

### 核心代码片段
- `startTask`函数：启动任务并连接SSE

### 为什么是核心代码
前端界面是**用户交互的核心**，SSE连接是实现实时更新的关键机制。没有SSE连接，前端无法实时显示扫描进度和结果。

### 核心在哪里
1. **SSE连接管理**：
   - **EventSource创建**：创建EventSource连接到SSE端点
   - **消息处理**：处理不同类型的SSE消息（start、progress、find、end）
   - **连接清理**：任务结束时自动关闭连接

2. **任务状态管理**：
   - **运行中任务跟踪**：跟踪所有运行中的任务
   - **持久化**：将运行中的任务保存到localStorage，页面刷新后自动恢复
   - **状态同步**：同步任务状态，确保UI与后端一致

3. **事件处理**：
   - **进度更新**：根据progress消息更新进度条
   - **结果显示**：根据find消息显示扫描结果
   - **任务结束**：根据end消息清理任务状态

### 作用
- **实时更新**：通过SSE实现实时显示扫描进度和结果
- **用户体验**：提供流畅的用户交互体验
- **状态管理**：管理任务状态，支持页面刷新后恢复

### 完整代码及逐行说明

#### startTask 函数

```javascript
function startTask(key, taskId, onMsg){
    // 第260行：关闭已存在的EventSource连接（避免重复连接）
    // running[key]?.es 使用可选链操作符，如果不存在则不执行
    if(running[key]?.es) {
        try{ 
            running[key].es.close()  // 关闭旧连接
        }catch{}  // 忽略关闭错误（连接可能已关闭）
    }
    
    // 第261-264行：创建新的SSE连接
    // sse函数内部创建EventSource，连接到 /events?task=taskId
    const es = sse(taskId, (m)=>{
        // 消息回调函数
        if(m.type==='end'){
            // 任务结束，清理运行中的任务记录
            delete running[key]
            persistRunningTasks()  // 持久化到localStorage
        }
        onMsg(m)  // 调用外部传入的消息处理函数
    })
    
    // 第265行：保存任务信息到running对象
    running[key] = { 
        id: taskId,  // 任务ID
        es           // EventSource对象
    }
    
    // 第266行：持久化运行中的任务到localStorage
    persistRunningTasks()
}
```

**关键点说明**：
- **第260行**：关闭旧连接避免重复连接，使用可选链操作符安全访问
- **第261行**：`sse`函数封装了EventSource的创建和消息处理逻辑
- **第262-264行**：消息回调函数处理end消息，自动清理任务状态
- **第265行**：`running`对象跟踪所有运行中的任务，key是任务类型（如'ps'、'ds'）
- **第266行**：`persistRunningTasks`将任务状态保存到localStorage，支持页面刷新后恢复
