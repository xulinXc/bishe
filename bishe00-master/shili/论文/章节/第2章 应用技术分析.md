# 第2章 应用技术分析

## 2.1 开发程序选择

为了给用户提供一个方便、快捷且易于维护的操作界面，本文综合比较了命令行界面、传统桌面图形界面以及基于浏览器的 B/S 网页三种实现方式。

命令行界面具备灵活、轻量和可脚本化等优点，适合专业人员进行批量操作与自动化调用，但学习成本较高，需要用户熟悉大量命令参数，不利于统一展示任务进度、结果列表和报告汇总。对于需要同时承载端口扫描、目录扫描、POC 验证、文件上传、报告查看与 AI 交互的综合平台而言，仅采用 CLI 形式会增加使用门槛。

传统桌面图形界面能够提供较强的本地交互体验，但跨平台部署和后续维护成本较高，版本分发也相对不便。对于毕设场景和教学环境来说，如果后续需要快速更新功能模块或部署到不同实验环境，桌面 GUI 的适配成本相对较大。

基于浏览器的 B/S 模式则兼具跨平台、无需安装、易维护和便于集中部署等优势。用户只需通过浏览器访问系统即可完成参数配置、任务发起、实时查看和结果导出，前后端职责划分清晰，也便于将长任务状态、报告聚合和页面恢复机制统一组织。因此，本文最终采用基于浏览器的 B/S 架构作为 NeonScan 2.0 的整体实现方式。

## 2.2 技术能力分析

一体化安全扫描平台需要同时处理多类高并发网络任务、文件上传、规则解析、外部工具调用、前端实时推送和 AI 交互，因此对后端语言的并发能力、网络编程能力和工程化部署能力提出了较高要求。Go 语言在这些方面具有明显优势。

首先，Go 语言通过 goroutine 和 channel 提供轻量级并发模型，能够较好地支持端口扫描、目录扫描、Web 探测、POC 验证等大量 I/O 密集型任务。对于需要同时维护任务状态、推送 SSE 消息和执行多模块联动的系统而言，Go 的并发模型能够在保证代码结构清晰的同时提升整体执行效率。

其次，Go 标准库 `net/http`、`encoding/json`、`os`、`sync` 等组件较为完善，可以直接支撑 HTTP 服务、JSON 数据交换、文件上传处理、并发同步和资源清理等核心需求。系统中统一任务管理、SSE 事件流、JADX MCP 会话通信、AI 请求转发和上传目录隔离等能力，都可以在 Go 单体服务中高效实现。

此外，Go 语言具有静态编译、部署简单、跨平台支持良好、运行效率较高等特点，能够生成单一可执行文件，便于在 Windows、Linux 等环境中快速运行。对于毕业设计场景而言，这种技术路线既降低了部署复杂度，也有利于系统后续维护和演示。

## 2.3 Go 语言介绍

Go 语言是由 Google 公司开发的一种静态类型、编译型并发编程语言，于 2009 年正式发布。Go 语言的设计目标是提高开发效率，同时保持代码的简洁性、可读性与执行性能，因此在网络服务、云原生应用、分布式系统和工具型软件开发中得到了广泛应用。

Go 语言的重要特性包括：goroutine 轻量级并发机制，适合创建大量并行任务；channel 通道机制，适合在并发流程中进行消息传递与同步；interface 接口抽象，便于组织可扩展的模块边界；defer 机制，便于资源释放和错误路径清理；丰富的标准库，能够直接支持 HTTP、JSON、文件、正则、加密和网络通信等常见需求。

在本系统中，Go 语言不仅用于实现 HTTP 服务和前后端接口，还用于组织统一任务流、并发扫描、规则解析、SSE 消息推送、AI 调用适配以及 MCP 会话通信。其简洁的语言特性和良好的工程化能力，使其非常适合承载 NeonScan 2.0 这种轻量但功能较综合的一体化平台。

## 2.4 HTTP 服务器与 RESTful API

HTTP（HyperText Transfer Protocol）是 Web 应用最基础的应用层协议，采用请求—响应模式实现客户端与服务器之间的数据交换。浏览器向服务端发送请求，服务端处理后返回响应结果。由于 HTTP 协议天然适合前后端分离式交互，因此非常适合作为本系统的通信基础。

RESTful API 是基于 HTTP 的一种接口设计风格，其核心思想是将系统能力抽象为资源或操作接口，并通过统一的 URI 与请求方法进行访问。RESTful 设计具有接口清晰、易于扩展、易于调试以及便于前端调用等优点。对于扫描平台这类多模块系统而言，RESTful 风格能够较好地组织端口扫描、目录扫描、POC 验证、文件上传、AI 分析和 MCP 状态查询等接口。

本系统采用 Go 标准库 `net/http` 实现 HTTP 服务器，并通过 JSON 格式完成前后端数据交换。系统当前提供的主要接口包括：端口扫描接口 `POST /scan/ports`、目录扫描接口 `POST /scan/dirs`、POC 扫描接口 `POST /scan/poc`、EXP 执行接口 `POST /scan/exp`、Web 探测接口 `POST /scan/webprobe`、WAF 绕过接口 `POST /scan/waf`、AI 自动扫描接口 `POST /ai/auto-scan`、Python EXP 生成接口 `POST /ai/exp/python`、批量生成接口 `POST /ai/exp/python/batch`、上传接口 `POST /upload`，以及用于实时推送消息的 SSE 接口 `GET /events`。这些接口共同构成了系统统一的服务入口。

## 2.5 SSE 事件流技术

SSE（Server-Sent Events）是一种基于 HTTP 长连接的服务器单向推送技术，客户端可通过浏览器原生的 `EventSource` 接口持续接收服务端发送的实时消息。与轮询方式相比，SSE 可以减少无效请求，提高实时性；与 WebSocket 相比，SSE 在只需要“服务端推送到前端”这一场景下实现更简单，也更适合本系统的任务进度展示需求。

SSE 消息通常采用文本流格式输出，每条消息以 `data:` 开头，以空行结束。服务端可连续推送任务开始、进度更新、发现结果和任务结束等不同类型的消息，客户端则根据消息内容实时更新日志区、进度条和结果列表。

本系统使用 SSE 技术组织统一任务反馈模型。当前前端通过 `EventSource` 连接 `GET /events` 接口，后端在任务执行期间持续推送 `progress`、`find`、`end` 等消息类型，并将任务 ID、进度文本、百分比和结果数据一并返回。该机制使用户能够实时感知长任务状态，也是页面刷新恢复和统一任务管理的重要基础。

## 2.6 MCP 协议

MCP（Model Context Protocol）是一种面向模型与外部工具交互的协议，用于规范模型如何发现工具、调用工具并处理返回结果。通过统一协议抽象，模型服务与工具能力之间的集成关系可以更加清晰，也便于构建可扩展的会话式分析系统。

MCP 协议通常涉及工具定义、参数描述、请求响应、上下文管理和流式交互等内容。相比直接将外部工具逻辑硬编码在系统内部，MCP 更适合承担“会话上下文 + 工具能力”的桥接角色，尤其适用于需要持续对话、连续分析和上下文保留的场景。

在 NeonScan 2.0 中，MCP 技术当前已明确落地为 JADX MCP 会话分析能力。系统通过 `/mcp/jadx/connect`、`/mcp/jadx/configure`、`/mcp/jadx/messages`、`/mcp/jadx/status` 和 `/mcp/jadx/chat/stream` 等接口，与 JADX MCP 服务建立连接并维护会话状态。前端可据此查看连接状态、历史消息与流式分析输出，从而将 APK 反编译辅助分析纳入与 Web 扫描一致的统一平台框架中。由此可见，MCP 协议不仅扩展了系统能力，也为平台后续接入更多会话式工具提供了技术基础。
